# Public Surface Policy

The public surface is everything a visitor can read before cloning or installing Shiroe.

## Primary surfaces

- `README.md`
- `SECURITY.md`
- `CONTRIBUTING.md`
- `AGENTS.md`
- `docs/TRUST_AUDIT.md`
- GitHub releases
- GitHub wiki

## Rules

1. Do not claim comparative leadership without reproducible external evidence.
2. Do not claim production readiness without a named release gate.
3. Do not hard-code test counts unless generated by the release process.
4. Do not link to deleted tags.
5. Do not publish private paths, credentials, internal notes, or user-specific data.
6. Keep historical material in `CHANGELOG.md`.
7. Separate facts, assumptions, unknowns, and risks in public docs.
8. Keep the README concise.
9. Make security reporting private and obvious.

## Public claim levels

| Level | Allowed wording |
|---|---|
| Verified local | Full local test suite passed and `shiroe doctor --json` returns `status: pass`. |
| Fixture verified | Adapter fixture passed locally. |
| External verified | Named external command was run with reproducible output. |
| Comparative | Named tools were compared with dated methodology. |
| Not allowed | Best, world top, 10/10, production-grade, or secure by default without proof. |
